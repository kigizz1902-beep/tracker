# PRD: 독서/영화 기록 트래커

*(Notion 단일 데이터소스로 확정)*

---

## 1. 개요

- **프로젝트명**: 독서/영화 기록 트래커
- **한 줄 설명**: 책과 영화를 다 본 뒤 제목/평점/한줄평/완료일을 기록하고, 카드형 갤러리 화면에서 조회하는 개인용 웹 애플리케이션
- **데이터 저장소**: Notion 단일 소스 (이미 구성된 "독서영화트래커" 데이터베이스 활용)
- **버전관리/배포**: GitHub(버전관리) + Vercel(배포), 무료 플랜만 사용
- **대상 사용자**: 개발자 본인 1인 전용. 로그인/공유 없음

---

## 2. 문제정의

- 책/영화를 다 보고 난 뒤 소감을 남기는 방법이 메모앱, 종이 등에 분산되어 있어 기록이 유실되거나 일관성이 없음
- Notion 데이터베이스 자체의 기본 뷰만으로는 커버이미지 중심의 비주얼 갤러리 조회, 간단한 필터/정렬 경험을 제공하기 어려움
- 개인이 가볍게 쓸 수 있는, 기록과 조회에 특화된 전용 UI가 필요함

---

## 3. 목표 (Goals / Non-goals)

**Goals**
- Notion 데이터베이스를 백엔드로 하는 CRUD(조회/추가/수정/삭제) 웹 UI 제공
- 카드형 갤러리 뷰로 커버이미지·평점·한줄평·완료일 등을 한눈에 조회
- 책/영화 필터링, 완료일순·평점순 정렬 지원
- 무료 도구(Notion/GitHub/Vercel)만으로 구축·배포
- 개발 순서 준수: ① Mock 데이터로 화면 완성 → ② 실제 Notion 연동 → ③ 예외 처리 추가

**Non-goals**
- 로그인/인증, 다중 사용자 지원 없음
- 커버이미지 자동 검색(외부 메타데이터 API 연동) 없음 — URL 직접 입력만 지원
- 실시간 협업, 공유, 알림 기능 없음

---

## 4. 핵심기능

| 기능 | 설명 | 우선순위 |
|---|---|---|
| 갤러리 조회 (Read) | 카드형 그리드로 커버이미지/제목/유형/평점/한줄평/완료일/상태 표시 | P0 |
| 새 기록 추가 (Create) | 제목/유형/평점/한줄평/완료일/상태/커버이미지URL 입력 폼 | P0 |
| 기록 수정 (Update) | 카드 클릭 후 평점·한줄평 등 필드 수정 | P0 |
| 기록 삭제 (Delete) | 카드에서 기록 삭제 (확인 방식은 Open Question) | P0 |
| Notion 연동 (CRUD) | Notion API를 통한 실제 데이터 읽기/쓰기 | P0 |
| GitHub 버전관리 | 저장소 생성 및 커밋 관리 | P0 |
| Vercel 배포 | 프로덕션 배포 및 환경변수 보안 처리 | P0 |
| 필터 (책/영화) | 유형별 필터링 | P1 |
| 정렬 (완료일순/평점순) | 정렬 옵션 (기본값은 Open Question) | P1 |
| 커버이미지 표시 | URL 기반 이미지 렌더링, 깨진 링크 시 대체 처리 | P1 |

---

## 5. 사용자 시나리오

- **A. 기록 추가**: 책을 다 읽음 → 앱 접속 → "새 기록 추가" 클릭 → 제목/유형(책)/평점/한줄평/완료일/상태(완료)/커버이미지URL 입력 → 저장 → 갤러리에 카드로 표시됨
- **B. 필터+정렬 조회**: 최근 본 영화만 보고 싶음 → 필터를 "영화"로 설정 → 정렬을 "완료일순"으로 설정 → 갤러리에서 확인
- **C. 기록 수정**: 다시 생각해보니 평점을 바꾸고 싶음 → 카드 클릭 → 평점/한줄평 수정 → 저장 → 갤러리에 즉시 반영
- **D. 기록 삭제**: 잘못 입력한 기록 발견 → 카드에서 삭제 액션 실행 → (확인 절차는 Open Question) → 갤러리에서 제거됨

---

## 6. 기술요구사항

- **프론트엔드**: React + Vite, Tailwind CSS, lucide-react(아이콘). 상태 관리는 `useState`/`useContext`만 사용하며 별도 상태관리 라이브러리는 도입하지 않음
- **데이터 소스**: Notion ("독서영화트래커" 데이터베이스, 속성: 제목/유형/평점/한줄평/완료일/상태/커버이미지)
- **Notion 연동**: 공식 SDK(`@notionhq/client`) 사용
- **개발 단계별 데이터 전략** (요청하신 순서 그대로):
  1. 1단계 — 정적 Mock 데이터(JSON)로 갤러리/폼 UI 완성
  2. 2단계 — Notion API 연동으로 교체, 실제 CRUD 동작 확인
  3. 3단계 — 예외 처리(네트워크 오류, 입력 유효성 검사, 빈 값 등) 추가
- **인증/보안**:
  - 개발 중에는 연결된 Notion 도구를 그대로 사용해 기능을 구현·테스트하며, 별도 서버 쪽 보안 처리는 미리 구현하지 않음
  - **배포 시에는 이 방식을 그대로 쓸 수 없음** — 배포 준비 단계가 되면 서버 쪽 코드(예: Vercel Serverless Functions)와 환경변수를 통해 토큰이 클라이언트에 노출되지 않는 방식으로 전환 필요. 구체적 방법은 배포 단계에서 결정
  - 인증 정보(토큰, 키 등)는 어떤 경우에도 프론트엔드 코드에 직접 넣지 않음
- **버전관리/배포**: GitHub 저장소(무료 플랜), Vercel 무료 플랜, main 브랜치 자동 배포
- **호환성**: 데스크톱/모바일 웹 브라우저 반응형 지원

---

## 7. UI 구성

- **메인 화면**: 카드형 갤러리 그리드 (커버이미지 썸네일, 제목, 유형 배지, 평점, 완료일, 상태 배지, 한줄평 요약)
- **상단 바**: 유형 필터(책/영화), 정렬 선택(완료일순/평점순), "새 기록 추가" 버튼
- **추가/수정 폼**: 모달 또는 별도 페이지 (제목, 유형, 평점, 한줄평, 완료일, 상태, 커버이미지 URL 입력 필드)
- **카드 상세**: 카드 클릭 시 수정 폼 노출, 삭제 버튼 포함
- **빈 상태(Empty state)**: 기록이 없을 때 안내 문구 및 "새 기록 추가" 유도
- **반응형 레이아웃**: 모바일 1~2열, 데스크톱 3~4열 그리드

---

## 8. 성공지표

- Notion 연동 CRUD(생성/조회/수정/삭제)가 오류 없이 동작하는지
- 갤러리에서 필터/정렬로 원하는 기록을 즉시 찾을 수 있는지 (체감 탐색 용이성)
- Vercel 배포 후 페이지 로드 실패나 API 키 노출 이슈가 없는지
- 실제로 책/영화를 볼 때마다 기록을 남기는 습관이 유지되는지 (주관적 사용 빈도)

---

## 9. 향후고려사항

- 커버이미지 자동 검색(외부 도서/영화 메타데이터 API 연동)
- 태그/카테고리, 검색 기능 추가
- 통계/대시보드(연간 독서량, 평균 평점 등) 시각화
- 다중 사용자, 로그인/공유 기능 (현재는 명시적 Non-goal)

---

## 부록: Open Questions (지어내지 않고 남겨둔 미정 사항)

**아래 항목들은 아직 확정되지 않았으니 임의로 결정하지 말 것.** 구현 중 이 항목과 관련된 결정이 필요하면 먼저 사용자에게 확인한다.

- 정렬 기본값 (완료일 최신순 vs 평점 높은순 등)
- 삭제 시 확인 절차 방식 (확인 모달 vs 즉시삭제 후 되돌리기 등)
- 평점의 범위/형식 (1~5, 1~10, 소수점 허용 여부 등)
- "읽는 중" 상태처럼 완료일이 없는 기록의 정렬/표시 처리 방식
- 커버이미지 URL이 깨졌을 때의 대체 이미지/플레이스홀더 구체 사양
- 기록이 많아질 경우 페이지네이션/무한스크롤 적용 여부
- 배포 시 Notion 토큰 보호의 구체적 구현 방식 (서버리스 경유는 확정, 세부 캐싱/레이트리밋 전략 등은 미정)
